# LLM agent orchestration in 2025–2026: frameworks are dying, loops are winning

**The dominant trend in agent orchestration is radical simplification.** Every major AI lab now ships its own lightweight SDK, MCP has become the universal tool-integration standard with **97 million monthly downloads**, and the developer consensus has shifted decisively: a plain while-loop with native tool calling handles 80% of production use cases. LangChain isn't dead—it still commands **126k GitHub stars** and 28 million monthly downloads—but its role has narrowed to complex enterprise workflows via LangGraph, while the broader ecosystem moves toward composable, framework-minimal patterns. Anthropic's influential "Building Effective Agents" guide crystallized the philosophy now adopted industry-wide: **"The most successful implementations use simple, composable patterns rather than complex frameworks."**

The agent market reached **$7.84 billion in 2025** and is projected to hit $52.6 billion by 2030. Gartner predicts 40% of enterprise applications will embed task-specific AI agents by end of 2026, up from less than 5% in 2025. Yet 73% of enterprise agent deployments fail reliability expectations in their first year, and the gap between a compelling demo and a production system remains vast. What follows is a detailed map of the frameworks, patterns, protocols, and hard-won production lessons defining this space right now.

## The great framework unbundling: what actually replaced LangChain

LangChain didn't get replaced by one thing—it got unbundled by many. The company itself pivoted, publicly stating that **"new agents should be built using the LangGraph library"** rather than core LangChain. According to one analysis, 45% of developers who experimented with LangChain never deployed it to production, while 23% of adopters eventually removed it entirely. The persistent complaints—dependency bloat, breaking changes, overcomplicated abstractions—drove a diaspora across multiple lighter alternatives.

**LangGraph** absorbed LangChain's agent ambitions. With **28,200 GitHub stars** and 34.5 million monthly downloads, it models agents as finite state machines with explicit state, branches, loops, and checkpointing. Around 400 companies deploy it in production, including Cisco, Uber, LinkedIn, and JPMorgan. Klarna's LangGraph-powered support bot handles two-thirds of all customer inquiries, reportedly replacing 853 employees and saving $60 million. LangGraph's graph-based orchestration gives teams fine-grained control over state persistence, human-in-the-loop checkpoints, and execution replay—but its learning curve is steep, and for simple agents it remains overkill.

The real story of 2025 is that **every major AI lab shipped its own agent framework**. OpenAI released the **Agents SDK** in March 2025 (19k stars, 10.3 million monthly downloads) with deliberately minimal primitives: Agents, Handoffs, Guardrails, and Tracing. Google launched the **Agent Development Kit** at Cloud NEXT in April 2025 (17.8k stars, 3.3 million downloads) with multi-language support across Python, TypeScript, Java, and Go. HuggingFace released **smolagents** (26.3k stars), whose entire agent logic fits in roughly 1,000 lines of code. Anthropic shipped its own Agent SDK. Microsoft merged AutoGen with Semantic Kernel into the unified **Microsoft Agent Framework**, putting AutoGen into maintenance mode.

**Mastra** emerged as the breakout framework of 2025—the third-fastest-growing JavaScript framework ever measured. Built by the ex-Gatsby.js team, funded by a $13 million seed round led by Y Combinator, it reached **22k GitHub stars** and 1.77 million monthly npm downloads after hitting v1.0 in January 2026. Mastra fills a critical gap for TypeScript developers: LangChain's JS library "always felt translated from Python," as one reviewer put it. Replit's Agent 3, PayPal, Adobe, and Marsh McLennan (deployed to 75,000 employees) run Mastra in production.

**PydanticAI** (16k stars) has become the "dark horse" for teams that need type safety and structured output validation—a "FastAPI feeling" for agent development. **CrewAI** (47.4k stars, 5.2 million downloads) remains strong for role-based multi-agent workflows but benchmarks show it consumes nearly 2x the tokens and takes 3x longer than alternatives on simple tasks. **Agno** (formerly Phidata, 39.1k stars) positions itself as "no graphs, chains, or convoluted patterns—just pure Python."

The pattern is clear: the framework market has fragmented along language lines (Python vs. TypeScript), ecosystem lines (OpenAI vs. Google vs. Azure), and complexity lines (minimal SDK vs. full orchestration). No single framework "replaced" LangChain—the entire category disaggregated.

## The 50-line agent loop that won production

The most consequential shift in agent development is not a new framework but the realization that **native API tool calling has made most framework abstractions unnecessary**. Claude, GPT-4o, Gemini, Qwen 3.5, and Llama all support multi-step tool calling as a first-class API feature. The canonical production pattern—validated by Claude Code, which Andrej Karpathy called "the first convincing demonstration of what an LLM Agent looks like"—is a single-threaded while-loop:

```python
while True:
    response = llm.chat(messages, tools=tool_definitions)
    if not response.tool_calls:
        return response.content
    for call in response.tool_calls:
        result = execute_tool(call)
        messages.append(tool_result(call.id, result))
```

This pattern, expanded to roughly 50 lines with error handling and iteration limits, **handles 80% of agent use cases in production**. Claude Code itself uses exactly this architecture—a while-loop that continues as long as the model returns tool calls. O'Reilly published a working coding agent in 131 lines of Python. HuggingFace's "Tiny Agents" implements an MCP-powered agent in about 70 lines.

The "just use the API" movement has articulate advocates. Jerry Liu, co-founder of LlamaIndex, was "unusually candid" about coding agents disrupting his own product: "The central value proposition was always: 'This is boilerplate. We wrote it so you don't have to.' Coding agents now deliver on that same promise, but far more flexibly." On Hacker News, the top-voted response to "Which LLM framework does agents the right way?" reads: **"None of them. You are better off coding up your workflow in some normal language, like Python."** Harrison Chase of LangChain conceded: "You don't need a framework for everything."

Three factors drove this shift. First, **LLM APIs matured**—native tool calling, structured outputs, and long context windows are now built in. Second, **coding agents** like Claude Code and Cursor disrupted the core value proposition of framework boilerplate. Third, **MCP standardized tool integration**, removing the need for framework-specific connectors. The emerging production stack is simply: plain Python + model SDK + MCP.

There's an important caveat about model selection for tool calling. The industry has split into "Thinking" models (optimized for reasoning, like DeepSeek R1) and "Acting" models (optimized for reliable tool execution). Reasoning models tend to reason *about* tool calls rather than making them—a subtle, hard-to-debug failure mode. For tool-calling agents, **non-thinking mode is preferred**: faster, more predictable, more reliable. Claude Opus 4.6 can chain an average of 21.2 independent tool calls without human intervention. Google's Gemma 4 ships with native function calling and structured JSON output. At the edge, FunctionGemma—a 270-million-parameter model—runs tool calling on phones with 550MB RAM.

## Beyond ReAct: the orchestration pattern landscape has matured

ReAct (Reason-Act-Observe) remains a foundational pattern but is no longer dominant in isolation. A 2025 paper titled "Beyond ReAct" explicitly calls out its **"inherent local optimization traps"**—it makes incremental decisions without strategic planning, errors cascade through sequential steps, and token costs accumulate as the observation log grows. For dynamic, few-step exploration tasks, ReAct still works. For anything requiring planning over more than 5–8 steps, production teams have moved to richer patterns.

**Anthropic's five workflow patterns** have become the most widely referenced architecture guide in the industry. They draw a sharp distinction between *workflows* (LLMs orchestrated through predefined code paths) and *agents* (LLMs dynamically directing their own processes). The five patterns are: **Prompt Chaining** for sequential processing, **Routing** for input classification and specialized handling, **Parallelization** for concurrent subtask execution, **Orchestrator-Workers** for dynamic delegation, and **Evaluator-Optimizer** for iterative improvement loops. Their core recommendation: start with the simplest pattern that could work, and add complexity only when you hit clear limitations.

**Plan-then-Execute** has gained significant traction as an alternative to ReAct's incremental approach. A powerful reasoning model generates a comprehensive multi-step plan upfront—potentially as a structured JSON or DAG—and then cheaper executor models carry out each step. This provides predictability, auditability, and up to **90% cost reduction** by limiting expensive frontier model invocations to the planning phase. The key risk is brittleness: a static plan assumes tools succeed, so production implementations add dynamic replanning when steps fail.

**DAG-based execution** represents the leading edge of parallel agent orchestration. Instead of linear step sequences, a planner generates a directed acyclic graph with explicit dependency tracking. Independent nodes execute concurrently; dependent nodes wait for predecessors. The LLM Compiler pattern, documented by LangChain, and Flash-Searcher (a 2025 paper) both demonstrate significant latency reductions on research-heavy tasks. Google's ADK provides native `ParallelAgent` and `SequentialAgent` primitives for this purpose.

**State machines** (LangGraph's core abstraction) dominate when workflows need loops, retries, conditional routing, and durable execution. LangGraph compiles workflows into validated, immutable graphs at build time, with checkpointing that survives failures and enables time-travel debugging. For complex stateful systems—multi-turn conversations, approval workflows, long-running research tasks—this remains the most production-tested approach.

The **Reflection pattern** (generate → evaluate → revise, typically converging in 2–3 iterations) has proven "surprisingly effective" for code generation, writing, and data analysis. **Multi-agent orchestration** with a supervisor delegating to specialized workers outperforms single agents on complex tasks—Anthropic's multi-agent research system outperformed single-agent Claude Opus by **90.2%** on their internal evaluation. However, a May 2025 paper found that the benefits of multi-agent systems diminish as frontier model capabilities improve; the expensive mistake is "jumping to complex patterns prematurely."

## MCP became the TCP/IP of agent tooling in 18 months

The Model Context Protocol's trajectory from Anthropic side project to industry standard happened faster than almost anyone predicted. Created in November 2024 by developer David Soria Parra (inspired by the Language Server Protocol), MCP reached **97 million monthly SDK downloads** by March 2026. Over **5,800 MCP servers** and 300 clients exist, with unofficial registries indexing more than 16,000 implementations.

The adoption cascade was swift. OpenAI adopted MCP in March 2025—Sam Altman said "People love MCP and we are excited to add support across our products." Google DeepMind confirmed Gemini support in April. Microsoft announced Windows 11 MCP integration and Copilot Studio support. AWS Bedrock added MCP in November 2025. In December 2025, Anthropic donated MCP to the **Agentic AI Foundation** under the Linux Foundation, co-founded with Block and OpenAI, and backed by Google, Microsoft, AWS, Cloudflare, and Bloomberg. Jensen Huang of NVIDIA declared that "the work on MCP has completely revolutionized the AI landscape."

MCP's architecture follows a Host–Client–Server model using JSON-RPC 2.0. Servers expose three primitives: **Tools** (functions for the AI to execute), **Resources** (context and data), and **Prompts** (templated workflows). The protocol supports local (stdio) and remote (HTTP/SSE/Streamable HTTP) transports. The latest specification (version 2025-11-25) added asynchronous operations, statelessness support, and official extensions.

Complementing MCP, Google launched the **A2A (Agent-to-Agent) protocol** in April 2025 for inter-agent collaboration—where MCP connects agents to tools, A2A connects agents to each other. These are complementary, not competing: MCP gives agents "hands" while A2A gives them "colleagues." OpenAI contributed **AGENTS.md** as an agent instruction standard, now adopted by 60,000+ open-source projects. Together, these three protocols form the emerging standard stack for agentic AI.

**Security remains MCP's critical vulnerability.** Researchers have documented prompt injection attacks, tool poisoning (malicious servers injecting hidden instructions in tool descriptions), "rug pull" attacks (tools mutating their definitions after installation), and supply chain compromises. The `mcp-remote` npm package (437k+ downloads) had a critical remote code execution vulnerability. An unofficial Postmark MCP server was modified to silently BCC all emails to an attacker. The MCP specification prioritizes interoperability over security—authentication, authorization, and access control are left to implementors. Enterprise-grade OAuth 2.1 integration isn't expected until Q2 2026.

## Geospatial agents: PostGIS meets the agentic loop

The geospatial AI agent ecosystem has matured rapidly from proof-of-concept to production tooling. The dominant pattern mirrors general agent architecture: an LLM generates spatial SQL or Python code, executes it against PostGIS or a geospatial library, reads errors, self-corrects, and re-executes—a true agentic loop adapted for spatial reasoning.

**Mundi** (by Bunting Labs, AGPL-3.0 licensed) is the most complete open-source example: an AI-native WebGIS that uses PostGIS as its core execution engine. Presented at PostGIS Day 2025, it demonstrates the iterative query-execute-debug loop that defines geospatial agents. **Felt** showed a production approach at the same event, teaching Claude to handle the ambiguity of spatial language—converting vague terms like "near" and "inside" into measurable geographic parameters (buffers, spatial predicates) and interpreting SQL errors as "schema tips" to guide the model back to working queries.

Research benchmarks confirm that **domain-specific approaches dramatically outperform general-purpose models** for spatial SQL. Aino AI, built on a fine-tuned Mistral-7B with 2,000+ PostGIS-specific training prompts, achieved near-human accuracy on spatial SQL generation, while GPT-4o and Claude 3.5 scored below 60% on the same tasks. The GeoJSON Agents paper (2025) compared function calling (85.71% accuracy) against code generation (**97.14% accuracy**) for geospatial analysis—code generation wins for complex, open-ended spatial tasks, while function calling provides more stability for structured operations.

The **MCP ecosystem for geospatial** is developing quickly. Dedicated PostGIS MCP servers (like `receptopalak/postgis-mcp` and PostGIS Yukon MCP with 32 spatial tools) standardize how LLMs access spatial databases. Mapbox ships an MCP server for geocoding, routing, and isochrone analysis. QGIS, GeoServer, and OpenStreetMap all have MCP bridges. Ian Ward of Mapbox articulated the emerging **GeoAI stack at the GeoAI 2026 Forecast**: LLMs + MCP as bridge to tools and data + agent frameworks + live geospatial data.

Key benchmarks include **GeoSQL-Eval** (14,178 instances, 340 PostGIS functions, 82 thematic databases—the first end-to-end automated evaluation framework for PostGIS query generation) and **GeoBenchX** (202 geospatial tasks using a ReAct agent built with LangGraph and 23 specialized tools). GeoBenchX found that making tools more narrowly specialized improved agent accuracy—a finding consistent with broader agent design principles. The multi-agent "From Questions to Queries" framework achieved 87.7% accuracy on spatial text-to-SQL through staged interpretation, schema grounding, logical planning, SQL generation, and execution-based review.

## What actually works in production: context engineering and radical simplicity

The LangChain State of Agent Engineering Survey (1,300+ respondents, late 2025) found that **57.3% of teams have agents in production**, up from 51% the prior year. But the hard-won lessons are more instructive than the adoption numbers. Quality, not cost, is the top barrier—**32% cite quality** as their primary challenge, while cost concerns have dropped. The universal finding: reaching 80% quality happens quickly, but **pushing past 95% requires the majority of development time**.

The paradigm shift from "prompt engineering" to **"context engineering"** defines the production maturity curve. As one practitioner put it: "The LLM doesn't experience your architecture. It sees one context window." Metabase discovered that independently optimizing different components created contradictory signals in the context window—they weren't building a querying tool with context features, they were building a context engineering system. The three patterns that survived: optimized data representations, just-in-time instructions, and actionable error guidance.

Production systems that work share common characteristics. They use **single-threaded agent loops** (not multi-agent swarms) for debuggability. They implement **human-in-the-loop** at critical decision points—every successful production deployment includes it. They route across **multiple models** by task complexity and cost (75%+ of teams use multiple models). They invest heavily in **observability** (89% have implemented tracing) long before they invest in evaluations (only 52%). And they bound agent autonomy: Salesforce's Agentforce ($540 million ARR, 18,500 enterprise customers) discovered drift after 8+ steps and responded with stronger deterministic triggers and explicit human escalation paths.

The spectrum of what works in production has crystallized into three tiers. For **simple tool-calling agents**: use the API directly, plain Python + SDK, 50–100 lines of code. For **stateful or complex agents**: use a lightweight SDK (OpenAI Agents SDK, PydanticAI, Claude Agent SDK, Google ADK). For **enterprise multi-agent orchestration**: LangGraph or CrewAI may justify their complexity—but even LangChain now advises teams to "build less and understand more."

MCP was the dominant topic at **TDC Summit IA São Paulo 2025**, with multiple speakers adapting presentations last-minute to cover it. PipeRun became the first Brazilian CRM with embedded MCP integration, homologated with OpenAI and Anthropic.

Brazilian enterprise adoption is led by major banks. The **UFG (Federal University of Goiás)** has mapped over 50 Brazilian-developed LLMs since 2020, reflecting a growing domestic AI ecosystem. Rocketseat, with over 1 million Brazilian developers, published a widely-read Portuguese MCP explainer calling it "a universal context bus for AI."

## Conclusion: the agents that ship are boring

The clearest signal from two years of agent development is that **production-grade agents are architecturally simple**. The while-loop won. MCP standardized the toolbox. Native API tool calling eliminated most framework abstractions. The frameworks that thrive—LangGraph, Mastra, OpenAI Agents SDK—succeed by being thinner, not thicker.

Three insights stand out as genuinely new. First, **context engineering has displaced prompt engineering** as the critical production skill—managing what enters the context window matters more than how you phrase instructions. Second, **the model taxonomy now splits "Thinking" models from "Acting" models**, and using a reasoning model for tool calling causes subtle, hard-to-debug failures. Third, **MCP's security model is its Achilles' heel**—the protocol achieved universal adoption before solving authentication, authorization, and supply chain integrity, creating a window of vulnerability that won't close until at least mid-2026.

For teams starting today, the practical advice is convergent across every credible source: begin with a simple agent loop using native tool calling, add MCP for tool integration, instrument with tracing from day one, and resist the urge to add multi-agent complexity until you have clear evidence that a single agent with the right context isn't sufficient. The agents that survive production aren't the most sophisticated—they're the most debuggable.
